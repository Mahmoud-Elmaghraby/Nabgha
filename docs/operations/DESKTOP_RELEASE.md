# إصدار نسخة الديسكتوب — قايمة تحقق

> **الحالة:** معتمد · **آخر تحديث:** 2026-11-25
> المرجع الكامل للـ installer ومشاكله: [`../INSTALLER_DEEP_DIVE_v2.md`](../INSTALLER_DEEP_DIVE_v2.md)

نسخة الديسكتوب بتتحدّث عند العميل بـ installer واحد بيشتغل في وضعين: تثبيت جديد أو تحديث.
مع كل تشغيل للبرنامج، `migrate.js` بيطبّق أي migration ناقصة على كل المراكز اللي على الجهاز.

## 1. قبل البناء
- [ ] الفرع متدمج ومتجرّب (type-check + build + `pnpm test:scenarios`).
- [ ] `CHANGELOG.md` متحدّث، ورقم الإصدار متحدد.
- [ ] الـ migrations الجديدة متجرّبة على **نسخة من قاعدة بيانات عميل حقيقي** (مش بس schema فاضية).
- [ ] مفيش migration بتعمل `GRANT` لاسم ثابت (DB-001).

## 2. البناء
```bat
:: كـ Administrator على جهاز ويندوز
build-installer.bat
```
الناتج بيتحط في `releases/` (متجاهل في git).

## 3. التجربة قبل التوزيع
- [ ] **تثبيت جديد** على جهاز نضيف: إعداد المركز ← دخول ← إضافة طالب ← حضور بالسكانر ← طباعة PDF.
- [ ] **تحديث** فوق نسخة فيها بيانات: البيانات موجودة، والـ migrations الجديدة اتطبّقت (`schema_migrations`).
- [ ] النسخ الاحتياطي اشتغل قبل التحديث.
- [ ] بعد التشغيل بـ 3 دقايق: نسخة تلقائية (`nabgha-backup-auto-*`) ظهرت في الإعدادات ← النسخ الاحتياطي، والكارت أخضر "آخر نسخة سليمة".
- [ ] الطباعة: PDF عربي سليم (الخط مضمّن)، وليبل على طابعة الليبل بمقاس "الحجم الفعلي".
- [ ] الواتساب: الاتصال بالـ QR ورسالة تجريبية لرقمك الشخصي.

## 4. التوزيع
- عند **عميل واحد الأول** لمدة يوم أو اتنين، وبعدين للباقيين (ROADMAP A3).
- بلّغ العميل: "أول مرة هتحتاج تسجّل دخول من جديد". ده بيحصل لما فيه تغيير في التوكنات زي اللي في AUTH-012.

## 5. migrations لازم تتطبّق في الإصدار الجاي (من آخر installer اتوزّع)

| # | الأثر عند العميل |
|---|---|
| 025 | تعديل أو حذف مصروف بيصلّح رصيد الخزينة |
| 026 | رصيد التعويض الجديد |
| 027 | التسميعات، وربط الامتحان بالحصة، والدرجة النهائية بكسور |
| 028 | **إصلاح حرج:** إضافة أسئلة من البنك لامتحان كانت بتفشل (EX-011) |

> حدّث الجدول ده بعد كل إصدار (امسح اللي اتوزّع).
