# ADR-0001: Schema منفصلة لكل مركز في PostgreSQL

- **الحالة:** معتمد (موثّق بأثر رجعي)
- **التاريخ:** 2026-11-25

## السياق
نبغة بيشتغل في 3 أوضاع: ديسكتوب عند العميل، وسيرفر في السنتر، وسيرفر سحابي فيه مراكز كتير. محتاجين عزل قوي لبيانات كل مركز، ونسخ احتياطي واسترجاع لمركز واحد بسهولة، ونفس الكود يشتغل في الأوضاع التلاتة.

## القرار
- كل مركز ليه schema اسمها `tenant_<uuid>`. والـ public schema فيها المراكز والخطط ومستخدمي المنصة (Prisma).
- الوصول لبيانات المركز بـ Kysely: `getTenantDb(tenantId)` = `withSchema(...)`.
- الـ migrations ملفات SQL بأرقام، وبتتطبّق على كل schema، وليها سجل في `<schema>.schema_migrations`.

## النتائج
- ✅ عزل قوي، وقاعدة بيانات واحدة، ونسخ احتياطي لمركز لوحده.
- ⚠️ **الـ SQL الخام ودوال plpgsql مش بياخدوا الـ schema تلقائي.** ده كان سبب ATT-011 وEX-011. القاعدة في [CONVENTIONS §2.1](../engineering/CONVENTIONS.md).
- ⚠️ الـ migrations لازم تتطبّق على كل schema (شوف ADR-0003).
